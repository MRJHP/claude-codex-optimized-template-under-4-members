# design-tracker

코드를 변경하는 동안 그것이 "설계 문서에 반영해야 할 변경"인지 판단하는 기준.

## DESIGN.md에 반영해야 하는 변경

- 새 모듈/서비스 경계 추가, 기존 경계 변경
- 데이터 모델/스키마 변경
- 외부 시스템과의 계약(API, 이벤트 포맷) 변경
- 이전에 기록된 ADR을 뒤집는 결정
- Codex와 상담해서 나온 아키텍처 판단

## 반영하지 않아도 되는 변경

- 버그 수정, 리팩토링(동작 불변), 테스트 추가
- 기존 설계를 그대로 따르는 통상적인 기능 구현

## 절차

1. 변경이 위 기준에 해당하면, [update-design 스킬](../update-design/SKILL.md)로 DESIGN.md의 ADR 섹션에
   새 항목을 추가한다.
2. 애매하면 사용자에게 "이 변경을 DESIGN.md에 기록할까요?"라고 짧게 확인한다.
