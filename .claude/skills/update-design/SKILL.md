# update-design

[.claude/docs/DESIGN.md](../../docs/DESIGN.md)를 실제 코드/결정과 어긋나지 않게 유지하는 절차.
언제 갱신이 필요한지는 [design-tracker](../design-tracker/SKILL.md) 기준을 따른다.

## 절차

1. 최근 변경(diff, 커밋, 대화 내용)에서 아키텍처에 영향을 준 부분을 추출한다.
2. DESIGN.md의 관련 섹션이 이미 있으면 갱신하고, 없으면 ADR 형식으로 새 항목을 추가한다.
   ```markdown
   ### YYYY-MM-DD <결정 제목>

   - **배경**: ...
   - **선택지**: ...
   - **결정**: ...
   - **Codex 의견**: (해당 시)
   ```
3. 오래되어 더 이상 사실이 아닌 내용은 삭제하지 말고 "(YYYY-MM-DD 기준 폐기됨, 이유: ...)"로 표시한다 —
   결정의 역사를 남기는 것이 목적이다.
4. 문서가 너무 길어지면(스크롤이 매우 길어짐) 오래된 ADR을 `.claude/docs/DESIGN_ARCHIVE.md` 같은 별도 파일로
   옮기는 것을 고려한다 (실제로 필요할 때만, 미리 만들지 않는다).

## 하지 말아야 할 것

- 코드만 봐도 알 수 있는 세부 구현(함수 시그니처 등)을 옮겨 적지 않는다. DESIGN.md는 "왜"에 집중한다.
- 사소한 변경(버그 수정, 리팩토링)마다 갱신하지 않는다.
