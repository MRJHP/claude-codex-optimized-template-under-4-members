# simplify

동작을 바꾸지 않으면서 코드 품질을 개선하는 절차. [coding-principles.md](../../rules/coding-principles.md)를
기준으로 삼는다.

## 검토 관점

1. **중복 제거**: 같은 로직이 3곳 이상 반복되면 공통화를 고려한다. 2곳 정도의 유사성은 무리하게 합치지 않는다.
2. **불필요한 추상화 제거**: 실제로 쓰이지 않는 확장 포인트(사용되지 않는 파라미터, 한 곳에서만 쓰이는 인터페이스)
   는 제거한다.
3. **가독성**: 깊은 중첩은 조기 반환으로, 긴 함수는 의미 단위로 분리한다.
4. **불필요한 방어 코드**: 내부 호출에서 일어날 수 없는 경우를 방어하는 코드는 제거한다
   ([security.md](../../rules/security.md)의 "시스템 경계에서만 검증" 원칙 참고).
5. **타입/린트 정합성**: `uv run ruff check . --fix`, `uv run mypy .`로 잡히는 문제를 함께 정리한다.

## 절차

1. 대상 범위(파일/모듈)를 명확히 한다.
2. 위 관점으로 개선점을 찾고 적용한다.
3. 동작이 바뀌지 않았는지 `uv run pytest`로 확인한다.
4. 변경 규모가 크면 리팩토링과 기능 변경을 같은 커밋에 섞지 않는다.
