# 코딩 원칙

- **단순성 우선**: 지금 필요한 것만 구현한다. 미래에 필요할지도 모르는 확장성을 위한 추상화를 미리 만들지 않는다.
  비슷한 코드 3줄이 섣부른 공통화보다 낫다.
- **단일 책임**: 함수/클래스는 하나의 이유로만 변경되어야 한다. 함수가 여러 단계를 섞어서 하고 있다면 분리한다.
- **조기 반환(early return)**: 중첩된 if/else 대신 가드 절(guard clause)로 예외 상황을 먼저 처리하고 빠져나간다.
- **불필요한 방어 코드 금지**: 내부 코드끼리 호출할 때는 타입/계약을 신뢰한다. 사용자 입력이나 외부 API 응답 등
  시스템 경계에서만 검증한다.
- **주석은 "왜"에만**: 코드가 "무엇을" 하는지는 좋은 이름으로 드러낸다. 주석은 숨겨진 제약, 트레이드오프,
  버그 우회처럼 코드만 봐서는 알 수 없는 이유를 설명할 때만 남긴다.
- **작게 커밋 가능한 단위로 작업**: 한 번에 너무 많은 것을 바꾸지 않는다. 리팩토링과 기능 추가를 같은 변경에
  섞지 않는다.
