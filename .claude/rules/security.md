# 보안 규칙

## 기밀 정보 관리

- API 키, 토큰, 비밀번호, DB 연결 문자열은 절대 코드나 커밋에 하드코딩하지 않는다. `.env` + 환경 변수로 관리하고
  `.env`는 `.gitignore`에 포함시킨다.
- 로그, 에러 메시지, 테스트 픽스처에 실제 시크릿 값을 남기지 않는다.
- 커밋하기 전에 `git status`/`git diff`로 실수로 포함된 자격 증명이 없는지 확인한다.
- 사용자 프롬프트나 파일에서 시크릿으로 보이는 값을 발견하면, 그 값을 그대로 출력하거나 외부로 전달(Codex 위임
  프롬프트 포함)하지 않는다.

## 입력 검증

- 시스템 경계(사용자 입력, 외부 API 응답, 파일 업로드 등)에서만 검증한다. 내부 함수 간 호출에는 과도한 방어
  코드를 추가하지 않는다 ([coding-principles.md](coding-principles.md) 참고).
- SQL은 파라미터 바인딩만 사용하고 문자열 포매팅으로 쿼리를 조립하지 않는다.
- 셸 명령을 조립할 때 사용자 입력을 직접 문자열 결합하지 않는다 (커맨드 인젝션 방지).
- 외부에서 받은 데이터를 신뢰할 수 없는 것으로 취급하고, 타입/스키마 검증 후 사용한다.
